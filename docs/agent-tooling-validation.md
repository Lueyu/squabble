## 已闭合的审查问题

- 状态机覆盖归档前取消、本地重解析审计、带未知关闭、编辑预览自环。
- 审批只有运行器一个所有者；混合批次先读后等待写入，不重新读取或重跑模型生成预览。
- 模型 step 与工具 invocation 分别预留；未知费用保留，迟到事实幂等修正。供应商零值占位和矛盾计数保持未知，额外 total tokens 不丢失。
- run 冻结实际数据版本集合和内容 hash，恢复不重新获取最新修订数据。
- 来源停用、删除、权限收紧不经审批、产物、解析或计算的迟到回调复活；清理回执不返回私有结果。
- 已确认终止的计算资源不会被迟到错误改回未确认；已知 sandbox ID 即使首个持久化回调失败也保留，404 视为已确认不存在，供应商原始错误不外泄。
- 浏览器采集有可引用证据；计算摘要来自已保存且复验过 owner/来源的结果，缺口影响 coverage，不由模型重构完整曲线。

## 验证方式与限制

所有数据库破坏性测试仅使用可丢弃 PostgreSQL16；供应商网络、OAuth、模型与应用写入使用
假传输，浏览器采集使用隔离 HTTPS 夹具。实际 Python 库的26项测试通过；旧 Python Agent
16项通过。实际浏览器检查覆盖1440px/390px、中英文、密钥输入遮蔽、目录审阅、预览编辑后
精确新 revision/hash 确认、确认后仅展示待恢复状态、未知结果无重发入口及无横向溢出。

完整 lint、Web 构建、Nest 编译装配、架构和 context 检查均单独运行；完整 server/client、
memory evaluation 及 CI 的最终结果见 PR。Windows 本地 native/dev 套件中的 POSIX 专属用例
按平台跳过，不能记为已执行。并发全套检查曾使旧 memory-race 的60秒父用例超时，必须在
低负载下重新执行，不能放宽测试或将该轮标记通过。

本次没有使用个人持仓触发付费研究、策略确认、模拟订单或真实应用外发。未配置服务保持
不可用；后续真实账号接入与质量验收使用明确指定的测试资源和独立记录。
