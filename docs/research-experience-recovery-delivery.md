# Squabble 持仓分析与投研室体验改版交付记录

> **历史交付记录。** 以下结果属于所列日期及改版，不替代当前验证。
> 当前功能与代码入口见[文档导航](README.md)和[代码阅读指南](code-reading.zh-CN.md)。

2026年11月6日，Asia/Shanghai。用户已批准功能设计、三阶段十四项开发任务，并要求整体UI活泼、轻松。

## 功能交付

| 任务 | 实现与验收 |
| --- | --- |
| 1 执行就绪 | 首页、日报和投研室沿用实际连接与显式模型配置，支持仅配置命名API连接的场景；OpenCode完整模型标识在执行前检查，应用内可修复配置；冷启动先保存问题并返回回执；重启后只恢复可确认尚未派发的初始化。 |
| 2 结果兼容 | 保留五段对象型details；兼容具有完整必需字段的顶层研究回复，仍执行长度、类型、证据和交易约束。 |
| 3 真实进度 | 普通话题和组合也有生命周期事件；保存逐成员尝试、接纳状态与安全错误，不暴露原始stderr或私有思考。 |
| 4 原讨论恢复 | 重新整理已有文本、单成员重试、查看原文及查询原任务；成功内容保留，未知派发不重放。停止与重试的终态分别验证。 |
| 5 并行研究 | 最多两位独立执行，逐位显示合格观点；他人的初稿不进入尚未提交成员的输入。恢复结果补充历史，不改写既有总结。 |
| 6 比例布局 | 桌面占主内容可用宽度92%，窄屏100%；抽屉不挤压房间，长链接、表格、代码不撑宽页面。 |
| 7 股友体验 | 柔和紫蓝色界面、股友头像、活动卡、统一恢复区；具体型号未知时使用可读标签，限制提议放入消息菜单。 |
| 8 今日分析 | 主入口前置，基础事实不冒充AI研究，摘要不包含内部JSON；支持手动更新、真实进度、计时和停止。停止后刷新不会自动重启。 |
| 9 导入衔接 | 持仓与待分析意图同一事务提交；冻结确认时的快照；重复请求不重复执行，旧导入不能覆盖新确认。 |
| 10 批次恢复 | 逐图持久化，离开页面仍执行；原图按账户和批次隔离，通常24小时保留，未确认终止的任务延后清理。 |
| 11 部分识别 | 有效行与问题行分别保留，人工修改不被迟到结果覆盖；关键币种缺失必须明确核对。 |
| 12 合并更新 | 重叠行不累加，冲突需确认，已有数量和成本可更新；支持先保存7张再补齐3张，不清除未出现的旧持仓。 |
| 13 识别性能 | 缓存环境探测并在配置/登录/运行错误后失效，分段计时；当前保留可靠的逐图执行，未启用来源归属尚未验证的两图批量。 |
| 14 综合验收 | 完成离线行为测试、数据库集成、真实本地Agent与截图联调、浏览器布局检查、升级一致性及独立审查。合入仍须通过仓库规定的三项CI检查。 |

## 真实本地联调

使用虚构持仓和现有本地连接，不对真实账户下单。测试任务目录与用户运行中的任务目录隔离。

Codex新初稿一次调用，约65秒，回复通过应用校验。OpenCode新初稿一次调用，约82秒，返回完整顶层研究字段；由保存文本离线验证兼容修复，未追加模型调用。用户原来Codex返回的对象型details已用真实结构离线复现，正式修复保留各段内容。

十张同账户虚构分页截图包含29个可见行、20个唯一证券及9处跨页重叠。每张最多调用一次，两个路径合计20次识别调用，失败不自动补跑。

| 路径 | 总耗时 | 首批结果 | 唯一证券完整正确 | 说明 |
| --- | --- | --- | --- | --- |
| 每张重新探测环境的基线 | 330.640秒 | 34.270秒 | 18/20 | 一张识别未成功，成功项保留。 |
| 复用检测缓存 | 278.657秒 | 38.497秒 | 20/20 | 数量、成本和现价均与样本一致，重叠行没有累加。 |

这是同一组小样本的两次实测，模型耗时与返回质量仍有波动，不能把约16%的总耗时差全部归因于缓存，也不能保证用户任何十张原图都达到同样结果。主要体验改善是逐张可见、可先核对、失败不重做整批。尚未采用新的云识别服务。

## 数据与界面验收

新装与旧库升级后重复执行34至36迁移，比较95张表、1,140列及默认值、1,035个约束、214个索引和4个触发器，目录一致。90张既有表的旧字段保留，13条虚构业务记录不变；未生成订单、交易、策略授权或自动交易任务。

浏览器检查390、1280、1440、1920、2560、2880宽度；房间比例约0.92或1，长链接、表格、代码及抽屉不造成页面横向溢出。用户阅读上文时到达新消息不强制滚动，输入框达到144px后内部滚动。另检查三种短窗口、深色界面和80%/125%/150%的CDP视口与DPR等效缩放；无头浏览器的键盘原生缩放未生效，未将其当作原生缩放验证。二十列表格保留96至102px可读单元格，并只在自己的容器横向滚动。截图位于本地忽略的output/playwright目录，使用虚构内容。

运行产物放在独立实例目录，保留旧实例静态资源。用户数据在升级前备份；连接修复仅写Squabble内的模型覆盖配置，不改全局OpenCode配置。测试与备份不进入提交。

## 审查与检查

独立需求审查和代码审查发现的导入快照竞争、旧确认覆盖、手动更新无效、模型修复按钮、缺失币种、停止后自动重启、取消后派发以及不确定任务清理问题，均补充回归用例后修复。

检查包括ESLint、双端类型检查、样式检查、服务端、客户端、原生Agent、数据库、记忆评估和启动构建。Windows原生测试中保留一个仅适用于POSIX的显式跳过；GitHub Linux检查覆盖该项。最终检查及合并记录以对应PR和交付回复为准。

用户可以从今日“开始分析”，或在导入确认后直接进入分析；进入投研室继续提问时，可以看到股友实际研究进度，并在原讨论中处理失败。
