# Squabble 产品重设计 — 从 11 个页面到 4 步流程

## 核心洞察

用户的心智模型是一条直线：

```
"我的持仓怎么样了？" → "AI 怎么看？" → "和 AI 团队聊聊" → "先模拟试试"
```

现在的产品有 11 个导航项、5 种独立页面，用户必须在 Analysis → Council → AgentBuilder → Paper 之间手动跳转，而且页面之间没有连接提示。**问题不是功能不够，是功能太散。**

## 设计原则

1. **每个页面只有一个主按钮** — 用户不需要选择，只需要点击
2. **功能之间有箭头** — 报告页有"讨论"按钮，讨论室有"试盘"按钮，永远指向下一步
3. **不学习就会用** — 第一次打开就知道该做什么，因为按钮名称就是用户的自然语言
4. **上下文自动传递** — 从报告进讨论室，报告自动加载；从讨论室进模拟盘，策略自动创建

---

## 新导航结构（6 项，替代 11 项）

```
🏠 首页     → 看持仓、今日盈亏、快速入口
📖 分析     → AI 报告（组合+个股）、深度研报
💬 研究室   → AI 团队讨论（含 Agent Builder 策略）
🧪 模拟盘   → 虚拟交易、策略监控、导入真实持仓
📁 记录     → 持仓+关注+交易（合并为子标签页）
⚙️ 设置     → 账号+模型+通知+主题
```

### 合并说明

| 旧页面 | 归入 | 理由 |
|---|---|---|
| Dashboard | 🏠 首页 | 不变，加"分析"快捷按钮 |
| Analysis + DeepReport | 📖 分析 | 合并为统一报告列表 |
| Council + AgentBuilder | 💬 研究室 | 讨论产出策略，策略驱动讨论 |
| Paper Trading | 🧪 模拟盘 | 不变，加"导入真实持仓" |
| Holdings + Watchlist + Transactions + Journal + Import | 📁 记录 | 子标签页，低频访问 |
| Settings + StrategyRules | ⚙️ 设置 | 不变 |

**三个操作：**
- **发送消息** — 和 AI 团队讨论（支持引用报告、引用持仓数据）
- **保存为策略** — 讨论结论一键转为模拟盘策略（价格触发条件、仓位限制）
- **生成新报告** — 用讨论产出更新原报告版本（v2 → v3）

**入口：**
- 从分析页"讨论这份报告"进入 → 报告自动加载为上下文
- 从首页"加入讨论"进入 → 上次讨论自动恢复
- 直接进入 → 空白讨论，可上传任何股票或话题

## 核心交互流（3 条主线）

### 流程 1：每日体检 → 讨论 → 试盘

```
首页 → 点击"分析今天的持仓"
  → 分析页生成日报
    → 点击"讨论这份报告"
      → 研究室自动加载报告，AI 团队开始讨论
        → 讨论结束，点击"保存为策略"
          → 模拟盘显示新策略卡片
            → 等待触发，自动下单，推送通知
```

**用户操作：4 次点击。**

### 流程 2：单独研究一只股票

```
分析页 → 点击 NVDA 标签
  → 显示 NVDA 深度研报 v2
    → 点击"讨论这只股票"
      → 研究室加载 NVDA 上下文，团队讨论
        → 点击"生成新报告"
          → 新版本 v3 生成并保存
```

**用户操作：3 次点击。**

### 流程 3：镜像真实持仓 → 模拟操作

```
模拟盘 → 点击"导入真实持仓"
  → 弹出预览：将复制 6 只持仓到模拟盘
    → 确认导入
      → 模拟盘持仓与真实一致
        → AI 盯盘代理在此基础上交易
          → 每笔成交推送通知
```

**用户操作：2 次点击。**

## 技术实现要点

### 1. 真实持仓 → 模拟盘镜像（新增 API）

```
POST /api/paper/mirror-real
```

```typescript
// 从 holdings 表复制到 paper_positions
// 初始现金 = 0（因为资金已"投入"持仓）
// 保留现有模拟持仓则先清空
async mirrorRealPortfolio(userId: string) {
  const realHoldings = await this.db.select().from(holdings)
    .where(eq(holdings.owner, userId));
  
  // 清空现有模拟持仓
  await this.db.delete(paperPositions)
    .where(eq(paperPositions.accountId, account.id));
  
  // 复制真实持仓到模拟盘
  for (const h of realHoldings) {
    await this.db.insert(paperPositions).values({
      owner: userId,
      accountId: account.id,
      ticker: h.ticker,
      market: h.market,
      currency: h.currency,
      company: h.company,
      shares: h.shares,
      avgCost: h.buyPrice ?? '0',
    });
  }
  
  // 现金清零（已全部"投入"）
  await this.db.update(paperAccounts)
    .set({ cashBalance: '0' })
    .where(eq(paperAccounts.id, account.id));
}
```

### 2. 报告 → 研究室上下文传递（新增 API）

```
POST /api/council/sessions
Body: { sourceType: 'report', sourceId: runId }
```

研究室创建 session 时，如果 `sourceType === 'report'`，自动：
- 加载报告的 `coreThesis`、`bullPoints`、`bearPoints`、`riskItems`
- 作为初始上下文注入讨论
- UI 显示 📎 已引用标记

### 3. 讨论结论 → 策略（新增 API）

```
POST /api/paper/strategies/from-council
Body: { councilSessionId, conclusions: { ticker, action, triggerPrice, ... } }
```

从研究室的讨论结论中提取可执行策略：
- 解析讨论产出中的操作建议（买入/卖出/持有/目标价）
- 转换为 AgentBuilder 的策略规则格式
- 存入策略表，等待模拟盘触发

## 实施优先级

| 阶段 | 内容 | 影响 |
|---|---|---|
| **P0** | `导入真实持仓` 按钮 + API | 模拟盘从"空账户"变为"我的镜像" |
| **P0** | 报告页加 `讨论这份报告` 按钮 + 上下文传递 | 打通分析→讨论流程 |
| **P1** | 研究室加 `保存为策略` 按钮 + 策略转换 | 打通讨论→模拟盘流程 |
| **P1** | 导航从 11 项简化为 6 项 | 降低认知负担 |
| **P2** | 首页改为快捷入口聚合页 | 提升日常使用效率 |
| **P2** | Holdings/Watchlist/Transactions/Journal 合并为子标签页 | 清理导航 |
