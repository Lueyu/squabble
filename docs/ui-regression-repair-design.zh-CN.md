# 股友身份与页面职责整改

本轮是对已批准的独立股友设计的纠正。用户明确要求股友绑定动物头像、投资页面与持仓分开，并回溯修好其余 UI。该要求更新原设计“四个日常入口”的导航取舍；新手主线仍为导入持仓 → 认识股友 → 创建团队，研究室按需使用。

实施步骤见[整改计划](ui-regression-repair-plan.md)，实际结果与未完成门禁见[验证记录](ui-regression-repair-validation.md)。设计要求不等于已经完成验收。

## 用户看到的结果

1. **投资总览**展示账户表现和比较；**持仓**有独立一级入口，查看和管理明确账户的持仓、现金、账本。首页账户卡仍进入对应 `accountId` 的持仓页。桌面、手机、搜索与返回归属一致。
2. **我的股友**中的每个独立 Agent 有持久化动物头像，创建和编辑时可选择。推荐模板提供默认动物；换岗位、模型或加入团队不更换头像。名册、团队选员、组织视图、研究选员和聊天展示同一身份。模拟账户继续叫“模拟账户”，避免与独立股友重名。
3. **导入保存**是首要动作，成功后提供“下一步：认识股友”。开始研究是单独的明确操作；不再导航到不存在的 `/today`。
4. **创建团队**保存启动前的表单草稿，刷新和去添加股友后可继续。已发出的创建请求沿用原始幂等身份；未知结果不能清空后重发。配置变化需要核对时，展示可操作的继续或保留已创建资源并结束当前流程入口。
5. **研究室与运行记录**反映真实选中的股友。单人聊天不展示虚构的多人默认阵容；团队记录进入现有委托详情。预算明确是上限，不能显示为已消费金额或编造下一交易日。
6. 中英文推荐和用户填写的工作方式实际进入持久化配置。普通页面使用清楚的名称和简短提示，详细权限、工具和连接设置折叠展示。

## 数据与历史

- 动物 ID 属于股友身份元数据，与模型连接、模拟账户 companion、岗位和权限分开。新增 additive migration，确定性回填已有名册，不修改不可变历史能力版本。
- 新会话和新团队委托冻结当时头像；历史缺头像时兼容原回退，不能重写既有发言或改变权限证明。
- 保留实盘/模拟账户隔离、来源授权、未知任务处理、模拟交易确认和现有账本接口。

## 方案选择

采用定向修复现有页面和身份链路，保留已批准的独立 Agent 功能，补齐持久身份、跳转和草稿恢复契约，并通过行为测试和浏览器交互验收检查实际结果。

## 验收

- 固定虚构数据，在 1440px 桌面和 390px 手机检查页面、弹窗、可见操作和无横向溢出。
- 完成保存持仓 → 添加带动物头像的股友 → 建队 → 选择同一股友聊天；验证刷新、返回、头像保存和历史快照。
- 导航到投资、持仓、模拟账户、委托记录，核对 URL、账户参数、高亮与返回位置；不存在的路由不能作为按钮目的地。
- 数据库 fresh/upgrade/replay 测试验证头像回填、更新、幂等、权限不变和历史冻结；浏览器写操作仅对虚构夹具。
- 必需检查与 PR 门禁通过后，沿用会话已授权的合并与本地部署流程，保护现有数据和服务。
