# Squabble 简化版产品功能说明

审阅稿 · 2026年11月6日

Squabble 为个人投资者提供一桌可以共同研究、相互质疑并跟踪判断结果的 AI 股友。用户每天看懂自己的持仓，随时提出投资问题，并观察这支 AI 团队共同管理的模拟账户。

本说明覆盖下一轮完整改版，替代上一轮面向用户的研报版本、策略发布和多实验管理流程。既有交易记录、研究依据和真实数据继续保留。本文用于审阅；产品改造将在用户确认后开发。

## 1 已确定的产品方向

| 决定 | 产品行为 |
| --- | --- |
| 日常从今日开始 | 首页首先回答持仓怎么样、发生了什么、有什么值得关注 |
| 保留独立投研室 | 用户可以自由讨论任何股票或投资想法，也可以从持仓、报告、交易进入 |
| 保留真实多 Agent 特色 | 显示实际参与者、彼此回应、事实核查及观点变化 |
| 自动运行一个 AI 对照盘 | 用户一次开启并确认范围后，团队持续研究和模拟，不逐笔要求确认 |
| 允许 AI 发现新股票 | 在用户确认的市场和风险范围内自主发现、研究和选择股票 |
| 删除研报版本管理 | 用户不再管理版本、采纳、分支、修订草稿或发布 |
| 删除策略配置流程 | 用户表达目标和限制；系统负责生成可执行条件并执行校验 |
| 日常只管理一个 AI 账户 | 首次可复制真实持仓，后续独立运行，不自动跟随真实交易 |
| 讨论不等于指令 | 聊天中的明确交易限制需通过简短确认卡应用 |
| 暂停含义统一 | 暂停后停止全部自动模拟交易，包括自动保护性卖出 |

目标用户是希望理解自己持仓、愿意与 AI 讨论、但不愿配置 Agent 工作流和交易规则的个人投资者。“无需学习”指无需理解系统内部术语，不代表取消投资范围、资金起点和风险额度的必要确认。

## 2 用户需要认识的三个入口

主导航只保留“今日”“投研室”“AI 投资”。设置固定放在辅助位置。手机使用相同的三个主入口，不另造操作体系。

| 入口 | 首屏内容 | 主要操作 |
| --- | --- | --- |
| 今日 | 持仓概况、重要变化、团队关注与分歧、AI 最近行动 | 查看持仓、问问大家 |
| 投研室 | 最近讨论、直接提问输入框、实际参与的 AI 股友 | 提问、回复、查看依据 |
| AI 投资 | 运行状态、表现、当前思路、最近操作、持仓 | 开启、问问原因、暂停或恢复 |

“我的持仓”从今日直接进入，包含持仓、关注、导入、真实交易记录。按日期查看日报是今日的次级入口。连接 AI、研究用量、通知与数据管理集中到设置。既有手动投资日记归入“我的记录”，不再另占主导航。

不新增独立的策略中心、报告管理中心、Agent 团队管理中心或模拟实验中心。

## 3 今日

### 3.1 首屏回答三个问题

1. 我的持仓今天怎么样：总资产、今日盈亏及主要贡献；缺少可信起点时显示无法计算，并指出缺什么。
2. 哪些变化值得关注：财报、重要消息、明显仓位集中、原有判断受到新证据挑战。
3. AI 团队今天做了什么：重要讨论、新关注对象、模拟操作或明确的继续观察理由。

首页最多突出三条重要事项，其他内容进入“查看全部”。没有重要变化时直接说明，不为填满页面制造交易建议或争议。

### 3.2 内容结构

顶部展示持仓概况和数据更新时间，下面是三句话以内的今日摘要。详细归因、长报告和完整图表点开再看。

一条重要事项包含对象、发生的变化、与我的关系和一个主要操作。示例：

> 某只重仓股发布了财报。团队对利润增长的持续性有不同看法。
>
> 问问大家

普通事项只有事实说明；确实存在有依据的不同判断时才显示“有不同看法”。共识、分歧和资料不足使用不同文案，不能把资料缺失写成看空，也不能用赞成票数冒充可信程度。

### 3.3 每日生成

默认按用户业务时区每天07:30准备当天摘要；首次打开当天页面且尚未生成时也可触发，同一天同一输入去重。可直接展示的盈亏和事实先出现，AI 摘要异步补充，不阻塞进入首页。

此时间采用各市场最近可获得数据，逐项标注数据截至时间，不把不同市场的收盘时点说成同一时点。重大新资料可更新当天摘要并附“更新原因”。服务器离线时不补造错过的日报结论或交易；恢复后生成当前摘要。

没有连接可用 AI 时，仍可查看持仓与确定性事实；显示“连接 AI 后可生成分析”。

## 4 持仓与分析

### 4.1 每日分析

按日期保存日报，默认显示当天最近一次完整结果。用户可看昨天和过去某一天，不出现版本号、采纳状态、发布状态或修订分支。

同一天分析更新时直接更新当前阅读内容，附一句实质变化说明和更新时间。生成失败时保留上次完整内容并标注时间；禁止把失败结果覆盖成空报告。

### 4.2 单股分析

从持仓、关注列表、搜索或讨论中的股票卡片进入。首屏展示当前判断、支持理由、主要疑点和下一步关注什么；财务数据、估值假设和来源按需展开。

主要操作为“问问大家”和“更新分析”。点击更新时任务去重、展示已有进度，不重复启动付费研究。

### 4.3 讨论后更新分析

讨论得出可引用的新结论后，系统自动整理到相关股票或持仓分析中，提示“已更新分析：原先的利润判断包含一次性收益，现已修正”。

一次尚未完成的发言、不可信的来源、无法确定股票身份或仍然未解决的关键争议，不覆盖成确定结论。可以显示“仍有分歧”或“资料不足”，保留各方理由。

旧交易中的“当时为什么这么做”打开当时保存的材料，明确日期和时间。该历史阅读页只解释过去，不提供采纳、切换版本或修改交易依据的操作。

## 5 投研室

### 5.1 开始讨论

点击“新讨论”立即输入问题，不出现创建表单。建议问题作为可选提示，例如：

- 我想买这家公司，帮我看看有什么问题。
- 我的持仓里最值得担心的是什么？
- 上次讨论的判断，现在有新证据了吗？

从股票进入时自动携带股票身份和最近分析；从日报进入时带入该日持仓快照和分析；从模拟操作进入时带入该笔操作及当时依据。输入框上方只显示可读的上下文标签，例如“正在讨论：某公司”。用户可移除误带的上下文。

股票名称存在歧义时才补问一次具体市场或代码。普通投资观点允许直接讨论，不强制每次绑定股票代码。

### 5.2 连续会话

标题根据首轮内容自动生成，允许手动改名。最近讨论可搜索并继续；回复某条消息即指定讨论对象。

长对话自动压缩已完成部分，但原始消息保留可查。用户不操作线程分支、续聊交接表或消息数量上限。新的实质问题可以建立新讨论，但不自动复制成多个相似会话。

用户可以在研究期间追加问题。新消息会在当前可安全中断的步骤结束后纳入下一步；它不会被静默丢弃，也不会自动撤销已成交记录。

## 6 AI 股友如何讨论

### 6.1 真实身份

使用已连接并由用户允许参与的本地 Agent 或模型连接。默认自动选择最多三个参与者；设置中可以更改默认成员，不要求每次配置。

名字、头像、实际执行来源和当前任务可见。职责按任务分配，不把某个模型永久设定为看多或看空。同一个执行来源扮演多个角色时明确标注，不能冒充多个独立 Agent。

一个 Agent 可用时可以进行单人分析，但不能显示“团队达成共识”。自动发现新股票并自主买入至少需要两个可用的独立执行来源；不足时等待复核。之前已验证的规则和确定性保护可以在总开关开启时继续执行。

### 6.2 讨论过程

默认过程为“分别研究 → 相互质疑 → 必要时补查 → 汇总当前判断”。

初始研究阶段共享相同的问题、事实快照及用户约束，但不展示本轮其他成员的初步结论。之前已经公开的合法研究仍可作为共同资料，因此界面称为“本轮独立研究”。进入讨论后，质疑必须指向具体主张或证据。被质疑者需要说明保留、修改或无法证实的部分。

有争议才增加补查轮次，默认最多两轮针对性补查。没有足够证据时允许结束为等待，不通过无限争论强行得出结论。

用户默认看到每位成员的短结论、关键依据和相互回复；完整分析可展开。只展示公开的理由和证据，不展示模型内部隐藏推理。

### 6.3 讨论结果

讨论小结固定回答四件事：已经确认什么、还在争论什么、目前怎么做、什么新信息会改变判断。

“什么都不做，继续观察”是完整结果。多 Agent 同意不等于事实已验证，多数投票不能绕过资金、报价或风险校验。

## 7 一起回访以前的判断

讨论中可验证的实质判断由系统记录，例如“下次财报能否验证毛利率恢复”。事件到来或到达复查日期后，系统将新证据与原判断对照，并回到原讨论形成一条回访。

默认每天每个账户最多自动回访三项；没有新证据时不重复召集全员。超过额度的项目保留等待状态，用户仍可手动打开。

回访说明哪些证据支持或推翻了原判断、谁改变了观点以及原因。股价短期涨跌本身不能证明研究结论正确与否。首版不做模型胜率榜、收益排名或人格能力评分。

## 8 AI 投资账户

### 8.1 首次开启

默认一个团队共同管理一个 AI 模拟账户。首次进入展示“用我的持仓开始”。

正常资料完整时只有一张确认卡：起点持仓和现金、允许投资的市场、可自主发现新股票、主要风险限制、费用滑点。点击“开启 AI 投资”后创建独立起点并开始运行。

默认允许的市场取当前真实持仓所属的受支持市场，用户可以在同一张卡上增加或移除美股、港股、A股。首版可自动发现和买入普通股票及非杠杆ETF，不支持期权、期货、卖空、融资或杠杆及反向ETF。

未持有任何资产时，入口改为“先导入持仓”；另提供次级“用模拟现金开始”，需要明确输入金额与币种，不预填虚构的真实资金。

现金、可售数量、限制状态或估值缺失时，逐项询问确实必要的补充内容。现金未知可以明确选择零现金假设；不能静默当成完整复制。缺少可验证估值时保存准备状态，待资料补全后才能启动。

### 8.2 初始限制与用户控制

本稿建议使用一组清楚的默认限制，不先提供三套难以区分的风险问卷。以下是产品初始额度，供本次审阅修改；它们不是收益或最大亏损承诺。

| 项目 | 建议默认 |
| --- | --- |
| 单只股票仓位上限 | 10% |
| 单笔新增买入上限 | 总净值的5% |
| 当日累计新增买入上限 | 总净值的5% |
| 当日普通买卖总额上限 | 总净值的20% |
| 总仓位上限与最低现金 | 90%与10% |
| 当日亏损触发限制 | 达到3%后停止新增风险，已授权的风险降低仍可执行 |
| 资产方向 | 仅做多，不借款 |
| 新建账户成交模型 | 每笔费用5 bps，滑点10 bps |
| 研究预算 | 沿用已设置的更严格预算；未设置时，每日最多启动6项自动研究任务，发现、组合评估、单股深研和回访共用 |
| 深度研究范围 | 每次最多3位成员、最多2轮补查、最多12次模型或Agent调用 |

完整额度可在开启确认卡的“查看限制”展开。开启后设置和聊天确认卡均可修改；额度扩大、市场扩大和模型预算扩大必须用户明确确认，AI不能自己修改。

初始真实持仓已超过某项比例时，先标记“继承的集中持仓”，限制进一步扩大；不因为导入就立即强制卖出。AI可以提出或执行符合原授权的逐步降低风险方案。

### 8.3 持续运行

用户开启后不再创建每日、月度策略或逐次点击发布。AI 根据现有持仓、新证据和候选机会制定当前计划，在约定范围内自行调整。

每天每个允许市场开盘前检查是否需要持仓评估；同一输入和当天已完成的研究直接复用，不重复启动全量研究。服务未在线时，恢复后只评估当前机会。重要公告、原判断失效和显著风险变化可触发额外研究，共享每日预算，影响已有持仓的风险研究优先。实时扫描只检查已验证规则，不每次调用大模型。

新股票可以来自已连接的只读搜索、公司资料和同行关系。每次发现最多接纳10个候选、最多选3个进入深度研究；代码、交易所、资产类型和行情身份必须再次验证。没有可用来源时显示“暂时无法发现新标的”，继续管理已知持仓，不编造候选。

AI对新增股票的首笔买入必须经过独立复核；已有、低风险且条件明确的规则可直接执行；需要语义判断的条件由单Agent补判；大仓位、重大分歧和高风险候选自动进入团队研讨。路线由系统选择，用户不用配置。

只在当前原币可用现金内买入。首版不自动换汇；跨币种资金不足时说明需要换汇，用户通过一个金额确认卡完成。研究可以提出其他币种机会，但不能把基础币种净值当成可支出的原币现金。

### 8.4 页面呈现

首屏依次展示：账户状态、从起点以来的表现、当前投资思路、最近行动。持仓和完整流水在下方；技术日志进入详情。

行动卡说明“做了什么、为什么、是谁参与判断”，并提供“问问原因”。需要进一步讨论时链接实际讨论过程，不能用事后生成的理由伪装成交前已有的判断。

观点变化后可以自动调整下一步计划；已经成交的理由和记录不被重写。资料失效时冻结受影响的新风险，并触发有预算的补研。

### 8.5 暂停与恢复

按钮统一为“暂停自动交易”。暂停确认成功后，全部自动买卖和自动保护性退出均停止，正在进行的相关研究停止或标记结果不得执行，未成交候选及预留取消。已完成成交保留。

恢复按钮先重新核对当前持仓、用户限制、数据和连接状态，再基于当前资料制定计划。不会补执行暂停或离线期间的旧指令。

用户即使只暂停AI投资，仍可主动在投研室研究。服务关闭时显示最后在线时间，不能继续显示实时运行。

## 9 讨论如何改变 AI 的行为

普通观点、问题和条件假设都属于研究信息，不能直接修改账户约束。例如“我觉得这只股票可能会跌”不会自动变成禁买或清仓指令。

用户明确表达“不要再买这只股票”“这只股票先别卖”“提高现金比例”时，系统给出一张影响清晰的确认卡。示例：

> 将某股票设为只持有、不再新增买入。已有持仓保留。
>
> 应用到 AI 账户

首版支持：禁买某股、完全禁止卖出某股、临时停止加仓、调整单股上限、调整最低现金、调整允许市场。期限默认持续到用户取消，用户说了日期时展示准确到期时间。

“禁止卖出”会覆盖该股自动止损，确认卡必须直说这一影响。含义模糊时只补问关键歧义。互相矛盾的限制不生效，解释冲突并让用户选择。

点击确认后，服务端原子更新限制，使旧候选失效，并返回“已应用”。网络重试不得重复操作。关闭确认卡或只说“听起来有道理”不视为授权。

当前生效的限制集中显示在AI投资设置中，可以撤销。临时限制到期时恢复确认卡中说明的仍有效设置，不补执行被拦下的旧交易；到期前后的实际影响都能查看。

## 10 收益对照与复盘

默认比较“AI账户”和“起点持仓保持不动”的收益，两者使用相同起点、估值币种及可获得数据。另有市场基准作为次级参考。

真实账户后续会产生不同交易和资金流，首版不承诺一条完整、可归因的真实盘收益对照曲线。页面保留真实持仓现状和“真实盘已变化”的提示；不能把真实盘盈亏直接当作同口径AI超额收益。这个口径选择是本稿待用户审阅的建议默认。

今日、本月、自选日期只是查看方式，不再创建三种策略对象。自动日/月复盘成为简短结论：主要操作、费用、收益变化、重要判断回访以及尚缺资料。

缺少行情、汇率、准确区间边界或公司行动对账时，相关收益显示未知并说明原因。观测回撤仅代表已记录净值点，不表示离线或盘中完整最大回撤。

只有一个日常活动账户。需要重新从真实持仓开始时，用户在账户设置中确认“重新开始”；旧账户和讨论保留为只读历史，不合并、不覆盖，不提供常驻实验切换器。

已有旧版自动账户的用户，首次切换时会看到其真实运行状态，可以直接暂停。系统用一张卡说明“旧自动交易将暂停，核对新的投资范围后继续”；用户确认接管后才停止旧自动化、取消旧候选并启用新授权，账本保留。仅打开新页面不会自动接管或扩大权限。多个历史账户且没有活动账户时，只在此次切换选择一次起点。

## 11 设置与异常

设置只保留用户能理解的事项：连接我的 AI、允许参与的成员、研究用量、投资限制、通知和数据管理。本机 Agent 自动检测后由用户连接；不自动读取不相关目录或替用户启动付费研究。

“本地 Agent”指本机运行的客户端；它调用的服务是否远程由实际连接决定，界面不承诺所有模型推理都在本地完成。标准A2A远程端点扩展不作为本轮必须完成项，现有本地接入继续复用。

| 情况 | 用户看到什么 | 系统行为 |
| --- | --- | --- |
| 没有持仓 | 导入持仓或用模拟现金开始 | 不虚构资产 |
| 没有可用AI | 连接我的AI | 保留事实数据与已有完整分析 |
| 只有一位AI | 单人分析 | 不伪造团队讨论；新股自主买入等待独立复核 |
| 某成员离线 | 该成员暂未回复，列出实际已完成结果 | 不伪造回答；高风险缺少复核则等待 |
| 研究预算耗尽 | 今日自动研究额度已用完 | 已验证规则可继续按授权运行，未完成研究等待 |
| 行情过期或交易单位不明 | 暂时无法模拟这笔交易及具体原因 | 不用旧价或猜测每手数量成交 |
| 暂无共识 | 仍有分歧及需要什么证据 | 等待或在已有授权内采取明确的风险降低动作 |
| 公司行动无法对账 | 需要核对持仓起点 | 暂停受影响执行，保留记录和数据缺口 |
| 服务断连 | 上次在线时间 | 恢复后重新评估，不补造历史交易 |

通知默认只报告重要变化、研究需要用户输入、暂停故障或模拟成交汇总。普通扫描和重复讨论状态不连续打扰。

## 12 删除与保留

| 原功能 | 新处理 |
| --- | --- |
| 研报版本、采纳、分支、差异编辑器 | 从用户产品中删除；内部决策依据快照继续保存 |
| 需要挑选报告版本的讨论入口 | 自动携带上下文；来源仅按需查看 |
| 场景、标题、团队、工作流创建表单 | 直接输入问题；自动判断任务与参与者 |
| 策略草稿、发布、每日计划模式配置 | 由持续授权下的系统计划替代 |
| 多实验创建和切换 | 一个日常AI账户；重新开始与只读历史放设置 |
| Agent搭建器主导航 | 改为连接与成员设置；不开放可视化编排 |
| 常驻心跳、候选技术状态和路由参数 | 改为自然语言状态，诊断信息按需展开 |
| 每笔成交的依据、实际执行者和旧记录 | 保留，只读且可追问 |
| 硬风控、资金预留、行情与所有者校验 | 保留并加强，自动执行 |
| 各Agent收益PK、胜率排名 | 本轮不做 |

## 13 核心使用示例

早上，用户打开今日，看到组合变化和一张“团队对重仓股有不同看法”的卡片。点击后进入投研室，问题与持仓资料已带入。

两位真实Agent分别研究，其中一位指出利润增长包含一次性项目，另一位核对后修改判断。系统更新单股分析，显示改动原因，无需生成新版本或采纳。

AI投资账户决定继续观察，页面显示原因和实际讨论入口。用户说“这只股票别再加仓”，确认简短限制卡后生效。

几天后新数据出现，原讨论收到回访。AI说明哪些假设得到了支持，在用户已确认的边界内自行决定是否调整模拟持仓。用户通过当前思路、行动记录和收益对照理解结果。

## 14 验收标准

产品验收使用至少5位未参与设计的试用者；至少4位无需讲解即可在10秒内找到持仓概况，在30秒内从股票发起问题。这个目标需要实际试用，不以开发者自测冒充达标。

功能验收必须包含：零配置新讨论；真实独立初始研究和相互回应；单人模式诚实呈现；报告更新但旧成交依据不变；一次开启后发现新股票并完成有依据的模拟；模糊聊天不改权限；明确约束确认后立即约束所有成交路径；暂停与迟到结果并发时零新增自动成交；缺资料时不编造结果；中文、英文和390px窄屏均可完成主流程。
