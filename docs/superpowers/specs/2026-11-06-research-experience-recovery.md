# Squabble 持仓分析与投研室体验改版功能设计

用户已于2026年11月6日批准实施。新增视觉要求：整体活泼、轻松，采用柔和色彩、股友头像和清晰状态卡。实施中，Asia/Shanghai。

本次改版解决五件事：导入后能直接看分析；聊天区域按固定比例布局且不溢出；股友研究有及时、真实的反馈；同账户多图导入更快且可恢复；投研室失败能解释、能在原讨论内恢复。保留今日、投研室、AI投资三个主入口。

建议默认流程：核对截图结果 → 确认持仓并开始分析 → 今日阅读简报 → 点击和股友聊聊 → 多人讨论。导入默认生成简报，不自动开启一场完整多人讨论。这是本稿待批准的产品选择。

## 1 本次故障调查结论

以下结论来自当前源码、截图对应的讨论记录、本地任务文件，以及 OpenCode 的只读配置和会话记录。调查没有重新发起模型调用，也没有修改配置。

| 问题 | 已确认的事实 | 对改版的要求 |
| --- | --- | --- |
| Codex 报告格式错误 | 09:34:13 至 09:39:37，任务运行约324秒并成功返回合法JSON。response.details 为包含5段文本的对象，应用要求字符串，因而拒绝整份结果。其余内容单独校验通过。 | 修正输出契约；对明确支持的旧格式无损转换；保留有效材料，允许重新解析保存结果。 |
| OpenCode 执行失败 | 约1.6秒失败。本次未指定模型；本地默认 deepseek-v4-flash 被解析为提供商名称，实际模型ID为空。配置中对应的完整标识为 gateway/deepseek-v4-flash。 | 执行前检查实际模型；尊重显式配置；给出修复入口，不把“已登录”当成“一定可执行”。 |
| 所有失败都提示连接AI | Codex已经完成研究，OpenCode有连接但模型配置有问题；页面仍显示“没有可用AI”。 | 分开显示连接缺失、配置问题、运行失败、内容待整理。 |

| 首页看不到可用分析 | 导入不启动分析；更新按钮隐藏；基础模板可占据“已完成”状态；摘要截取内部数据正文。 | 打通入口，区分数据与研究，使用用户可读的摘要字段。 |

Codex 离线复现只在内存中去掉 details 字段验证边界，正式修复必须保留其全部有效内容。OpenCode 的原始退出信息未持久保存，因此能确认模型配置及解析错误，不能恢复当时具体的底层错误文本。截图导入的五分钟来自用户反馈，尚无分阶段耗时基线，不与上述324秒聊天任务混为一谈。

## 2 产品范围与取舍

保留现有持仓、研究资料、讨论、模拟账户和交易限制。不重新引入报告版本、策略发布、团队创建表单或多实验管理。用户无需了解任务、回执、输出契约等内部概念。

本次只改研究与导入体验，不改变模拟交易授权、总暂停、风险约束或真实持仓与模拟账户的隔离。研究结果格式容错不能放宽交易和证据校验。

不把所有流程改成聊天：今日提供易读结论，投研室负责深入交流，导入负责核对数据。也不只加几个按钮：这次必须修复实际执行、结果接纳和恢复链路。

## 3 导入完成就能开始分析

### 3.1 导入出口

截图识别完成后，展示合并后的持仓及本次差异：新增、数量更新、成本更新、待核对。主按钮为“确认持仓并开始分析”，次操作为“仅保存持仓”。

确认后在同一数据库事务内保存已核对的持仓和待派发分析请求，提交后启动研究并进入今日。分析开始失败不回滚已经保存的持仓，页面明确显示“持仓已保存，分析尚未开始”，提供重试。重复点击或网络重试不会重复写持仓或重复启动研究。

持仓手动修改、CSV导入等入口也提供分析入口，不能只修截图路径。正在导入但尚未确认的数据不进入报告；确认部分结果时，报告显示覆盖范围。

### 3.2 今日首屏

顺序为持仓概况、今日持仓分析、最多三条重点、次要活动。分析主操作始终可见，不放在折叠区底部。

| 状态 | 页面内容 | 主要操作 |
| --- | --- | --- |
| 无持仓 | 导入说明与示例 | 导入持仓 |
| 有持仓，无AI研究 | 已保存的事实及可用股友 | 开始分析 |
| 等待执行 | 指定股友、排队原因、已等待时间 | 查看进度或取消 |
| 正在分析 | 真实阶段、实际执行股友、已运行时间 | 查看进度或停止 |
| 已完成 | 三句话以内摘要、主要风险、关注事项、数据截至时间 | 和股友聊聊；更新分析 |
| 部分数据缺失 | 已能确认的结论与具体缺口 | 补充资料或继续讨论 |
| 更新失败 | 保留上次完整结果，注明时间和本次失败 | 重试本次分析 |

数据快照准备完成不算AI研究完成。基础算术模板不能阻止首次AI分析，切换到可用AI后允许真正研究。同一天相同有效输入重复进入页面复用任务；新增持仓、更新关键行情或改变执行来源后可明确更新，不用浏览器刷新强迫重跑。

初次导入没有历史起点时显示“首次导入，暂无可比历史”。跨币种缺少可靠汇率时分币种展示；行情不可靠时标注数据截至时间与缺口。缺口摘要一行展开，不显示原始JSON、内部字段或长篇系统告警。缺失数据不补零、不用默认汇率制造完整数字。

### 3.3 分析进入讨论

“和股友聊聊”带入用户当前阅读的报告、对应持仓快照和时间。用户看到“基于这份持仓分析”，内部保存不可变引用。继续讨论不会偷偷换成另一份持仓。重要变化后可以提示“持仓已更新，是否基于最新持仓另起一轮”，用户无需管理版本。

默认每日自动准备一次简报，沿用业务时区与自动研究额度；用户主动更新也受既有用量预算约束。没有可用执行器时等待连接恢复，不能生成基础模板后标为AI已完成。

## 4 投研室固定比例与防溢出

用户明确要求固定比例，取消上一轮1400px固定宽度建议。

桌面视口宽度达到1280 CSS px时，聊天外框宽度为侧栏和页面内边距扣除后主内容可用宽度的92%，居中，两侧各留4%。小于1280px时使用主内容可用宽度的100%。侧栏展开、收起或窗口缩放可以改变可用宽度；消息数量、文本长度、成员数量和讨论状态不能改变外框宽度。

不使用相对整个浏览器的92vw，不让既有全局1600px上限干扰该页面比例。标题、成员、消息、输入区均允许收缩，长链接换行。代码块与宽表格只能在各自内容容器内横向滚动，页面不出现横向滚动条。

高度使用应用顶部栏以下的可用空间。标题和输入区留在房间内，消息区承担主要纵向滚动；输入框增长到限定高度后内部滚动。短窗口中压缩辅助信息，保留可见输入区；移动端适配动态视口和软键盘。

最近讨论与技术详情采用覆盖式抽屉，不改变房间宽度。收到新消息时只有用户位于底部才自动滚动；阅读上文时显示“有新消息”。

## 5 有真实在场感的AI股友

### 5.1 名称与状态

主要显示头像、Codex或OpenCode等真实名称、当前活动。具体模型已确认时可显示简短型号；未回报时显示“本地默认模型”，技术详情中解释，不在主界面暴露unreported。

连接就绪、已安排本轮任务、实际开始执行、结果已接纳是不同状态。不能用已选择的执行器列表假装这些成员已经发言。

点击发送后立即显示发送状态；服务器确认后显示“问题已收到，正在安排股友”。执行前检查模型配置，失败就直接给出可处理原因，避免让用户等几分钟才知道无法启动。

### 5.2 研究过程

每位股友有轻量活动卡：排队、正在分析、查阅资料、已提交观点、内容整理失败或执行失败。显示已用时、最近活动时间。没有新工具事件时，只展示服务器能确认的执行状态；失去联系则写“暂未收到新状态”，不声称仍在查资料。

同类工具事件合并展示，完整过程可以展开。活动卡不转发原始命令、工具参数、私有思考或敏感资料，也不制造随机输入动画或假发言。

组合、单股、普通投资话题和报告讨论都具备生命周期事件，不依赖股票代码是否存在。

### 5.3 独立判断和自然讨论

第一轮在互不冲突的执行连接上最多并发两位；第三位排队，同一执行资源仍尊重已有单任务锁。每位股友先根据相同冻结材料形成自己的观点。

通过校验的独立观点可以先给用户看，标注“初步观点，其他股友尚未完成”。这种展示不进入尚未完成成员的输入；其他成员提交或被明确跳过后，再进入相互质疑。不能通过提前广播首个答案破坏独立判断。

成员完成、明确失败、已确认取消或用户明确跳过后，解除该成员对首轮结束的等待。后续围绕具体观点回复：支持什么、质疑什么、依据是什么、是否改变判断。正文短而自然，复杂依据展开查看。最多两轮针对性补查，没有新分歧就结束。只有一位成功时显示“仅一位完成，尚未经其他股友交叉检查”，不称为共识。

已经开始交叉讨论后再重试某位股友，其独立研究仍使用原始冻结材料，不能读取已公开的他人观点。新结果作为补充观点出现，用户可据此继续讨论；不得静默改写已经完成的总结。

用户中途补充的问题保留并确认收到；涉及新持仓或新事实时排入下一轮，不静默修改正在研究的冻结输入。用户可以停止当前轮，再基于补充内容继续。

## 6 结果接纳与错误恢复

### 6.1 本次Codex错误的处理

统一模型输出说明和应用校验结构，明确details的类型、来源引用格式和长度。对details为有限层级、键值均为文本的已知兼容格式，无损转为分节文本；不任意转换复杂对象、不删除有效段落、不修造证据。

区分“模型完成”和“应用接纳”。保存原结果与独立的解析状态，失败时记录字段路径、期望类型、实际类型等安全诊断。主界面显示“已返回研究内容，正在整理”或“内容整理未完成”，而不是要求用户修改不存在的报告输出设置。

允许在原讨论点击“重新整理已有结果”，只运行本地解析，不发起模型请求。仍有无法可靠接纳的内容时，可以查看原始研究文本，但不得作为已验证结论或自动交易依据。

### 6.2 本次OpenCode错误的处理

本应用执行前校验实际provider/model。尊重已保存的明确模型，不因简化流程而丢弃。对本次连接，建议在Squabble内使用已配置的完整标识gateway/deepseek-v4-flash，不修改用户全局OpenCode配置；这是本稿包含的具体连接修复项。

不能可靠解析默认配置时，提供“选择可用模型”，不擅自换到其他供应商或付费连接。模型名称未知与模型配置无效分别处理。

### 6.3 恢复交互

| 情况 | 用户看到 | 可用操作 |
| --- | --- | --- |
| 没有连接股友 | 尚未连接AI股友 | 连接股友 |
| 模型配置错误 | 这位股友的模型配置需要修正 | 修复配置后重试这位 |
| 本地工具占用 | 正在等待另一项任务结束 | 等待或取消 |
| 已有结果但解析失败 | 研究已返回，内容整理未完成 | 重新整理已有结果 |
| 单位成员明确失败 | 这位未完成，其他观点继续保留 | 仅重试这位；先看已有观点 |
| 任务状态不确定 | 正在确认原任务状态 | 查询原任务或停止；不自动重发 |
| 全部成员失败 | 本轮没有可用结论，并列各自原因 | 重试可恢复成员 |

重试留在原讨论，保留原问题、资料、已完成观点和失败记录。只重试明确失败或已终止的成员，新尝试独立记录；重复点击不重复调用，旧任务迟到结果不覆盖新一轮。预算、暂停和取消在重试前重新检查。

页面只出现一个聚合问题区，避免“成员报错、没有AI、红色总错误”三次重复。详细诊断由用户展开。

## 7 同一账户的多张持仓截图

### 7.1 一个批次、一份持仓

上传后立即看到图片列表和每张状态，结果逐步进入一张合并表。“已完成7/10张，发现2处待核对”比模糊百分比更直观。离开页面不取消任务，返回或刷新可恢复。

识别结果分为可用行、待核对行和无法识别的图片。一行字段有问题不使整张有效内容消失；缺失代码、数量或币种等关键字段不猜测。单图失败继续其他图片；登录、额度或能力问题影响整批时才暂停。

只重试失败图片，成功结果与人工修改保留。新识别结果不得覆盖用户已确认的修改。可先保存已确认部分，明确还有多少图片或行未纳入。

### 7.2 跨图合并与持仓更新

按账户内的市场和证券身份合并，不能只按展示名称。重复页、重叠行且数值一致时合并来源，不累加数量。数量、成本或币种有冲突时展示原图来源并请用户确认该字段。

已有持仓支持数量和成本更新。提交前展示差异；未出现在本次截图中的旧持仓默认保留，不自动判定清仓。本期不增加完整账户替换或自动删除持仓功能。

一次确认在一个数据库事务中提交；提交时持仓已被其他入口修改则提示重新核对差异。同一批次允许先保存已确认部分，再保存后续核对结果；每次确认有独立幂等回执，仅提交新确认或新修改行，已保存行不重复应用。支持用户逐行回看来源。

### 7.3 处理速度与资料保留

先测上传、能力探测、启动、识别、校验五段耗时，减少重复探测。识别前检测图片尺寸与格式，保持文字清晰，保存原图供核对。

测试小批量多图路径，默认每组最多两张，且每行必须返回来源图片标识；无法可靠追溯就回到单图。只有执行器明确允许多任务时才用受控并发，不能绕过Agent锁。单图失败重试不重做整批。

批次状态与已识别结果持久化，原图存储在本地受权限保护的任务目录，不进入通用日志或Git。首次上传时说明刷新后可继续、原图通常自上传起保留24小时；仍在执行的任务保留至终止确认后清理。排队图片到期则停止该项并清理，执行中到期先请求取消；状态不能确认时提示清理待确认。重启时继续执行到期清理。原图过期后保留结构化结果和人工改动，来源入口标注“原图已过期”，失败图片需重新选择。服务重启对未确认执行状态先查询原任务，不能自动重复付费识别。

本期不新增云OCR供应商或强制安装大型识别组件。只有既有视觉接口由用户配置时才可使用，不自动把截图转交新的服务。

## 8 验收标准

| 场景 | 通过条件 |
| --- | --- |
| 确认导入 | 不寻找菜单即可进入今日并看到明确分析状态；重复点击不产生第二个分析任务。 |
| 今日摘要 | 无原始JSON、dailyLedgerFacts等字段；基础快照不会显示为AI已完成。 |
| 连接一致 | 仅连接本地股友也能启动日报；错误模型不会被标为可执行。 |
| 本次Codex结果 | 无损保留5段details及其余有效内容；本地重解析的模型调用增量为0。 |
| 本次OpenCode配置 | 空模型ID在派发前被发现；明确完整模型可以传到执行器。 |
| 反馈 | 点击即时有发送状态，服务器接收后2秒内展示任务回执；不是要求模型2秒内完成。 |
| 讨论 | 第一位完成即可看到合格初步观点；另一位的独立输入不包含这份观点。 |
| 失败恢复 | 一位失败不抹掉另一位结果；无需新建讨论；未知派发不被自动重放。 |
| 宽度 | 1280、1440、1920、2560、2880桌面视口及不同缩放下比例稳定；390移动视口可用；正文不会撑宽页面。 |
| 十张截图 | 可逐步查看结果、离开后恢复、仅重试失败项；重叠行不加总，冲突可核对，已有数量可更新。 |
| 导入安全 | 部分识别不清除旧持仓；事务故障无半批写入；用户修改不被迟到结果覆盖。 |
| 性能 | 同一模型与样本记录改版前后总耗时和首批可核对结果时间；不能以提前显示假进度冒充提速。 |
