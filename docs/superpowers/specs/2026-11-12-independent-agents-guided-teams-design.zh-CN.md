## 1. 用户应该如何理解 Squabble

> 导入自己的持仓，认识几位擅长不同事情的股友，组成自己的团队。团队从持仓副本开始自动研究和模拟交易。用户平时查看进展，有问题再去研究室询问。

用户只需要理解三个对象：

| 对象 | 用户能理解的解释 | 主要操作 |
|---|---|---|
| 股友 | 一位有专长、能记住授权信息的 AI 助手 | 添加、了解能力、聊天、邀请入队 |
| 团队 | 几位已有股友按分工共同工作 | 选成员、启动、看进展、调整、暂停 |
| 模拟账户 | 团队用来尝试操作的一本独立账本 | 查看持仓、现金、模拟成交和表现 |

“研究室”用于按需交流；“运行分析”解释工作过程与表现。运行器、Agent Card、DAG、trace、checkpoint 等实现概念只出现在开发文档或明确展开的高级视图中。

## 2. 已确认的产品决策

| 决策 | 本次采用的方案 |
|---|---|
| 第一次使用 | 导入持仓 → 认识并添加股友 → 创建自己的团队；研究室随后按需使用 |
| 模拟盘起点 | 默认复制用户确认过的持仓与现金快照；从模拟现金开始保留为可选方式 |
| 账户关系 | 创建后的模拟账户独立记账；后续真实账户更新不会覆盖团队模拟路径 |
| 团队运行 | 最后一步确认规则和费用约束后自动研究、决策、模拟交易；支持暂停和调整 |
| 股友复用 | 同一股友可参加多个团队，保持稳定身份和可追溯的能力版本 |
| 记忆边界 | 共享身份、能力和用户明确设置的通用偏好；团队内部记忆默认隔离；指定内容可明确分享 |
| AI 来源 | 引导用户连接自己的模型服务或可用本地助手；配置一次，后续复用 |
| 建设路线 | 先补独立股友基础，再贯通现有研究、团队、模拟执行与运行分析 |
| RSI / RL | 本轮延期训练功能；从基础层预留个体训练、评测和版本发布所需契约 |

以下默认交互细节是对上述已确认方向的具体化。调整时仍须满足易用性和权限、费用、账户边界。

<a id="usability"></a>
## 3. 易用性硬要求

1. 默认新手主线只有三个大步骤。每屏只有一个视觉上突出的主动作，标题说明当前要完成什么。
2. 普通配置页每屏最多三项必须由用户决定的内容。按独立决定计数，不能把多项要求合并成“其他设置”规避；导入核对表以异常聚合和逐项修正处理。
3. 已有可用连接时，添加股友和组队都不再次要求密钥、服务地址或模型标识。连接失效时直接定位原连接修复。
4. 默认模板提供完整、有限的可运行配置。用户不展开高级项，也能完成默认主线。
5. 模型档位、推理强度、并行度、岗位依赖、工具标识、重试参数和版本号默认收起；可理解的风险、资料和费用摘要保持可见。
6. 股友能力用“核对财报”“寻找反证”等动作描述。所有术语第一次出现时提供一句话解释；错误提示采用“发生了什么 + 下一步”。
7. 用户的每个确认对应一个明确结果：保存持仓、添加股友、启动团队。范围内的后续自动工作沿用启动约定；扩大资料、工具、费用或执行范围才需要重新确认。
8. 清单基于真实保存状态恢复。刷新、返回、断网或中途退出后，已完成步骤不重复创建，未提交内容尽量保留，未知结果先核对。
9. 日常页面直接回答：现在是什么状态、最近做了什么、为何等待、研究花了多少、下一步是什么。高级运行细节按需展开。
10. 首次流程的可用性必须通过真实新手任务验证，不能以“按钮变少”或页面截图代替。

<a id="first-use"></a>
## 4. 第一次使用的完整流程

### 4.1 第一步：导入我的持仓

页面标题：**先告诉我们，你现在持有哪些资产**。

- 复用现有截图、文件、文本或手动录入中实际支持的方式，只展示当前环境可用的入口。
- 识别后的核对页集中显示标的、数量、成本、现金、币种和快照时间；异常行优先呈现。
- 现金未知时明确要求补充或确认实际为零，不从截图推算卖出收入，不把缺失默认为零。
- 主按钮依次为“识别持仓”“确认并保存”；保存成功后展示“下一步：认识股友”。
- 空仓用户可以明确保存零持仓和现金。导入失败或暂时缺资料时保留草稿，允许补充；基础资产记录不依赖始终可用的 AI。
- 导入、修正和重复提交继续使用既有预览、幂等回执与账本规则，不因向导简化而改变其含义。

### 4.2 第一次需要 AI 时：连接一次

已有可用连接直接复用；需要 AI 识别持仓或创建股友时，才出现短向导：

1. 选择已发现的本地助手，或选择模型服务。
2. 仅在需要时填写 API Key；已知服务使用预设配置，提供“高级设置”修改地址和模型。
3. 检查连接并保存为默认连接，返回原步骤。

检查优先使用无模型生成的连通性、鉴权和能力查询。必须进行真实生成才能验证的连接，明确展示“发送一次测试”和费用说明，用户执行后才调用；不将这种测试藏在页面加载中。

默认连接是执行资源，多位股友可以共用。股友的身份、专长和记忆不由连接名称决定。软件只发现并使用支持的本地运行环境；缺少登录、安装或配套桥接时给出对应操作入口。

### 4.3 第二步：认识并添加股友

页面标题：**选几位股友，帮你一起看持仓**。

- 首屏推荐财报分析、公司估值、反方研究、风险复核、主持收束五种模板，分别解释“擅长什么”和“会交付什么”。
- 一次“添加推荐股友”将这些模板创建为真实的独立股友记录，再进入组队步骤；模板不是匿名运行者。
- 用户可以改名、换模板或只添加部分成员。股友卡优先显示名称、专长、可用状态、“聊一聊”和“加入团队”。
- 自定义入口使用“描述你想要的股友”：生成可编辑能力卡，显示职责、工具和资料范围，确认后保存。手工修改提示配置位于高级编辑。
- 试聊是可选验证步骤，创建基础股友不强制通过固定数量的考试。模板不自动扩大已有工具或资料权限。
- 外部接入使用“连接已有助手”：地址或 Agent Card → 发现能力与鉴权 → 检查 → 确认加入。文字描述辅助填写，不代替可访问的连接地址。

### 4.4 第三步：创建我的团队

页面标题：**让这些股友组成你的团队**。

采用三个短页，避免一屏展示组织画布和全部运行参数：

| 页 | 用户主要决定 | 系统提供的默认值 |
|---|---|---|
| 选择协作方式 | 选模板；团队名称可选修改 | 推荐研究团队；模板生成职责和有限协作流程 |
| 确认成员 | 确认已有股友与职责对应 | 从我的股友匹配合适成员；主持职责明确 |
| 检查并启动 | 阅读运行摘要、确认费用方式、启动 | 持仓快照起步、推荐运行节奏、有限仓位规则与资料范围 |

缺少必要股友时显示“先添加这位股友”，完成后返回组队，不通过填写一个模型连接暗中创建匿名成员。用户已有成员的名称、基础能力和 AI 连接无需重复填写。

启动摘要必须清楚呈现：

- **用哪个模拟账户**：快照时间、持仓、现金、币种；可展开核对。
- **团队会做什么**：定期研究，在已确认规则内进行模拟交易。
- **何时工作**：默认每个主市场交易日收盘后一小时研究一次，后续模拟执行遵守各标的市场时段与现有交易规则。主市场从持仓提出建议并在摘要中显示；无法唯一判断时由用户选择。
- **能用什么**：获准的资料、记忆和工具摘要。
- **费用如何限制**：单次与跨周期上限、已知费用和未知费用的处理方式。

已知可执行费率的连接使用金额与调用双重约束；未知费用的 CLI/A2A 只能准确限制本系统派发次数等可控资源。此时摘要写明“按调用次数限制，实际费用由服务商计费”，需要用户明确接受这种方式，不能承诺无法保证的金额上限。默认背景运行不绕过这一选择。

“启动团队”一次确认保存持续运行约定，并开始首个获准的研究周期。配置、资源或市场条件暂不满足时，落地页说明等待原因；不能把已建好团队显示成研究已经执行成功。

## 5. 完成引导后的页面与导航

主导航保留四个日常入口：**投资总览、我的股友、团队模拟盘、研究室**。辅助区域提供**资料与记忆、运行分析、设置**。资产与账户、日报、策略库和报告历史保持原路由可达，通过总览、团队或研究室中的相关入口访问。

| 页面 | 默认首屏 | 按需展开 |
|---|---|---|
| 投资总览 | 真实/模拟账户表现、团队近况、待处理事项 | 资产明细、日报、历史对比 |
| 我的股友 | 能力卡、可用状态、聊天与入队入口 | 版本、模型来源、记忆范围、工具配置 |
| 团队概览 | 当前状态、最近判断与模拟行动、费用、下一次运行、暂停 | 分工、组织画布、依赖、版本与详细预算 |
| 研究室 | 选股友、输入问题、讨论与结果 | 本次资料、主持人、有限预算和流程 |
| 资料与记忆 | 我提供了什么、哪些股友/团队可以使用 | 来源版本、撤销、具体记忆与分享记录 |
| 运行分析 | 股友/团队表现摘要、需要处理的异常 | 任务、步骤、调用与版本比较 |

首次首页按实际完成状态提供引导。完成以后不反复弹出向导；新增团队或连接故障时仅出现与当前任务相关的提示。

新“我的股友”使用独立入口，例如 `/friends`；现有 `/paper` 继续表达模拟账户并保留深链接。账户动物形象保留为展示信息，不自动变成具备权限和记忆的个人 agent。

## 6. 独立股友与团队职责

### 6.1 对象边界

| 对象 | 职责 | 不能混用的内容 |
|---|---|---|
| `AgentProfile` | owner 下稳定的个人身份、展示资料、生命周期 | 不等于账户、模型连接或团队岗位 |
| `AgentVersion` | 不可变能力配置：职责、提示配置、工具声明、输入/输出要求 | 不存密钥，不冻结实时权限，不改写旧运行 |
| 执行连接 | 模型服务、本地 CLI 或 A2A 的地址、鉴权和资源状态 | 多个人可复用；连接变更不创造新人 |
| 团队岗位 | 本团队职责、授权子集、引用的股友与版本 | 不覆盖个人基础配置，不直接代替股友档案 |
| 模拟账户 | 现金、持仓、订单、成交、估值 | 不作为人的身份或记忆所有者 |

运行快照同时保留 `agentId`、`agentVersionId`、`teamId`、`teamVersionId`、`roleId`、本次 `memberId` 和工作/尝试关联。现有岗位席位 ID 不能被全局股友 ID 直接替换。

同一股友可以参加多个团队；在单次讨论/复核中不能被当成两名独立个体。多个股友共用模型是合法配置，界面如实显示同源信息，不能由此宣称模型来源独立。共享 CLI 沿既有资源锁排队，不复制凭据或绕过并发限制。

### 6.2 能力与版本

股友声明可执行任务、工具范围、可接收输入和结构化交付。交付区分结论、证据、假设、风险、未知项和可选行动建议；不同专长允许不同的输出类型，不能把所有能力压成一个通用看涨概率。

更换人设、工具策略或模型策略生成新的配置版本。团队固定引用版本，更新时显示差异并形成新的团队版本及必要的运行约定修订。旧委托继续归属旧快照；当前权限撤销立即生效，不等待旧版本结束。

归档股友停止新选择和新派发，保留历史。已经派发的工作按原授权与当前权限结算；需要立即阻止后续发布和应用时使用暂停团队。正在使用该股友的团队进入待处理状态并提示替换，不能默默换成默认模型或另一位股友。

## 7. 记忆和资料范围

| 信息类型 | 默认可见范围 | 写入与分享 |
|---|---|---|
| 用户明确设置的通用偏好 | 按用户授权供相关股友使用 | 用户设置；不能把私聊或团队内容自动提炼到这里 |
| 股友个人记忆 | owner 与该股友的个人交流范围 | 与该股友的个人交流可延续；进入团队须明确分享指定内容 |
| 研究室多人会话 | 本次选定参与者与用户 | 默认不进入其他会话或团队；分享时指定接收方 |
| 团队内个体工作记忆 | 对应团队、股友和获准工作阶段 | 保留独立提交边界，按流程发布交付后才供后继使用 |
| 团队共享判断与复盘 | 对应团队内获准接收者 | 按职责与流程写入；不自动传播到其他团队 |
| 公共事实与用户资料 | 来源本身的有效授权范围 | 保留不可变版本、发生/发布时间与实际可获得时间 |

实际读取权限为用户有效授权、股友允许范围、团队/会话范围、本次工作范围和来源仍有效的交集。模板、总结、改写或转发不会扩大这个交集。

明确分享保留原来源、精确版本、原作用域和接收范围。来源删除、撤权或变更会影响后续检索、发布与执行；摘要不能成为绕过来源限制的副本。已经产生的成交与固定历史快照按原账本契约保留。

历史回放与以后训练只使用当时可获得的数据。资料的存储时间、公开发布时间和评测截止时间分别记录，防止后来的事实进入过去的输入。

外部 agent 只收到本次明确获准的必要资料。本地范围检查不等于能够控制对方内部记忆、保留策略或模型训练；相关能力未知时如实标示，并限制到受支持的有限任务。

## 8. 自动团队的运行约定

### 8.1 从一次确认到持续运行

新增持久化 `TeamRunAgreement`，记录团队版本、成员版本、绑定账户、来源与工具范围、运行节奏、主市场/时区、单次及跨周期费用/调用约束、仓位规则、修订和暂停状态。

每个研究周期由该约定生成一份新的有限委托，继续调用现有 Team worker 和 Council。周期有唯一幂等键与租约；同团队默认不重叠执行，不在预算周期内“重新获得无限额度”。在途预留和结果未知的费用继续占用相应额度。

每次派发、读取资料、接受结果、发布、应用策略及模拟执行时，复核当前约定状态、修订和有效权限。修改团队、换股友版本、扩大授权或调整费用后更新约定，不能沿用失效的启动确认。

持续约定默认只覆盖已授权的读取、隔离计算和本地模拟账本操作。外部写操作继续遵守现有逐项预览确认流程，不由“自动运行”一并授予权限。

### 8.2 决策到模拟成交

运行链路为：

```text
已确认的运行约定
  → 有限研究委托与输入快照
  → 股友交付、反证与负责人收束
  → 系统校验来源、仓位、账户、预算和适用交易规则
  → 记录自动决定及约定修订
  → 生成并校验策略预览，应用到该模拟账户
  → 既有模拟交易执行与账本
  → 团队复盘、可追溯的运行记录
```

自动采纳和应用必须记录真实的系统/agent 行为及所依据的运行约定，不能后台冒充用户点击。保留现有预览哈希、账户修订、接受的尝试、来源和最终事务复核；不绕过预览/应用契约。

风险股友提供解释和复核；确定性的额度、仓位、账户及市场规则由代码最终检查。证据不足、验证未通过或没有适合行动时，“保持观察/不交易”是有效结果。

后续周期读取团队自己的模拟账户。真实持仓只在创建时提供起点；用户更新实盘后，系统可提示存在差异，但不会自动重置团队账本或把新增资金当成投资收益。

### 8.3 暂停、恢复和未知状态

- 默认“暂停团队”撤销后续自动派发与应用权限，并暂停关联账户全部模拟交易，包括保护单；操作旁用简短文字说明影响。
- 可取消的在途工作请求取消；无法立刻确认的外部工作显示“正在停止/结果待核对”，保留费用结算，不显示为已停止或自动重发。
- 已暂停后到达的结果可按历史契约记录，但不能继续自动应用策略。状态围栏在最终发布/应用事务处生效。
- 恢复时读取真实状态、核对连接与权限，从下一个合法周期继续；不隐式补跑过去全部周期，不复活被撤权的旧任务。
- 归档团队保留只读历史，并按明确交接方式处理模拟账户规则；不会移动旧团队的历史业绩。

## 9. 研究室：明确参与者，明确结束

单聊选择一位股友，由该股友完成回复，不额外引入隐藏总结者。多人讨论选择已有股友，并指定其中一位承担主持职责；推荐流程为独立研究、一次质疑/回应阶段、主持总结。

默认仅暴露问题和参与者。资料范围、主持人及预算可以展开；人数沿用现有有限运行容量，超出时解释限制。按股友身份保留参与者，移除按 `provider:model` 去重的旧产品语义。

所有模型步骤、补查、工具使用和总结都进入同一个运行预算；预检时验证模板计划能装入上限，并预留收束额度。必要角色没有完成时，结果标为部分完成，不能把已知缺口包装为全员共识。

达到阶段/调用/时间/费用上限、用户停止、输入不足或不可恢复错误时收束。模型判断“没有新信息”可以建议提前结束，不能成为唯一终止保证；置信度趋同不代表结论正确。

终态至少区分完成、部分完成、失败、已取消、超时和预算耗尽；外部结果未知属于需要核对的状态，不伪造完成。完成页给出结论、分歧、证据、未知项和后续可做的事。用户继续提问才启动下一轮。

研究室没有默认模拟交易权限。分享内容给团队只使其成为候选输入，由团队按自身运行约定复验后使用；分享和策略应用分开记录。

## 10. 运行分析与个体评测

### 10.1 普通用户与进阶用户的两层视图

- 股友卡：最近任务、完成情况、常见问题、可读反馈；样本不足明确显示。
- 团队概览：当前周期、最近判断与行动、费用、等待原因与下一次运行。
- 运行分析：按股友、版本、团队、委托和尝试筛选，展开模型/工具步骤、耗时、用量、失败及验收。

统计区分执行成功、交付验收、被采纳、策略应用和实际成交，避免一个“成功率”混合不同含义。成员与父子任务成本不能重复累加；已知费用、估算、未知费用分别呈现。

### 10.2 不同执行来源的观测范围

| 来源 | 应记录的内容 | 必须保留的限制 |
|---|---|---|
| Squabble 自研运行器 | 可见模型请求/结果引用、工具动作、授权、状态、用量与验收 | 遥测导出不等于导出完整内容；只记录实际观测事实 |
| 本地 CLI 助手 | 进程证据、公开活动、可获得用量、返回结果与本地验收 | 内部调用、实际模型、全部工具或费用可能未知 |
| A2A 外部 agent | 派发、远端任务关联、公开状态、耗时、产物、取消与验收 | 不假设可见对方私有记忆、内部推理或全部工具链 |

跨系统 trace 需要双方明确支持上下文传递与观测能力，不能因使用 A2A 或 OTel 就承诺自动串起完整链路。

个人能力优先使用可定义任务的证据正确性、结构化交付、引用覆盖、人工反馈、成本与延迟进行评测。只有预测事件、期限和结果可定义时才使用校准类评分；不能对任意“信心”或估值报告直接计算 Brier 分数。

团队净值、回撤与成交结果属于团队结果。要归因到个体，需要对照、替换或消融实验；不把同一份收益直接分配为每位股友的训练奖励，也不按少量历史分数自动停用股友。

## 11. A2A 接入范围

名册与执行适配在 P0 预留外部来源；P4 交付真实 A2A 接入，不能用历史 `a2a` 报告枚举或 mock 演示宣称完成。

第一版闭环包含发现 Agent Card、鉴权、能力映射、注册股友、有限请求、任务/产物关联、查询、取消和本地验收。支持的协议版本与传输方式在 P4 子规格中根据实际联调目标固定，并由兼容性测试证明；对不支持的版本明确拒绝。

远端状态和本地接受/发布状态分开。取消请求成功不代表远端已经停止；未知任务先查询原关联。外部调用沿用既有预算、来源与幂等边界，不再建立第二套团队编排引擎。

能力不满足的岗位不提供该股友为可用候选，或明确说明缺少哪项能力；例如未通过结构化交付验证的外部股友不能静默承担负责人。高级认证和能力映射按需展开。

## 12. 为以后做个体 agent RL 保留的扩展

本轮只完成可以稳定延续的身份与数据契约，不实现 RSI 自动进化、训练控制台、自动改模型权重或生产中的自我修改。

现在保留：

1. 个人身份、能力/提示/工具配置版本、模型策略与未来 checkpoint 标识、代码/解析器版本。
2. 任务目标、固定输入与可获得时间、授权范围、公开动作、工具观察、最终产物、终止原因及轨迹完整性。
3. 独立的人工反馈、任务验收、成本与评测标签；标签规则和评测数据均版本化。
4. 私有 episode 导出接口与训练器适配边界。完整内容按独立授权管理，保留来源、删除和训练/验证分组关系；不扩大现有 Langfuse 元数据导出范围。
5. 候选版本、基线版本、独立测试结果、发布和回滚关系；团队更新版本沿既有显式更新流程。

现有运行恢复 replay 复用旧响应，不等于可供训练重采样的任务环境。以后实际开展 RL 时，独立实现可重置环境、训练/验证时间隔离、奖励定义、采样、权重更新和评测；算法所需 token、动作概率、采样参数等由具备能力的训练后端采集。

算法岗作品需要展示可复现实验、基线和独立测试改进，并解释数据泄漏、奖励设计和个体贡献。提示配置搜索可以作为一种优化实验，但不能替代真实权重训练的实验记录。训练框架通过适配器连接，不提前把产品绑定到某个框架。

### 13.2 迁移规则

- 持仓、现金、订单、成交、估值、旧团队及报告历史原样保留。缺少旧个人身份关联时标为旧记录，不按头像、名字、股票或时间猜配。
- 提供“从现有成员配置创建股友”的迁移入口；创建可审核的独立档案，不因同一模型而合并不同人设。
- 旧团队可以继续使用冻结旧版本；升级后建立股友引用并发布新版本，不覆盖旧运行快照。
- 旧账户形象不自动授予股友权限；重新组织导航时保留旧路由与资产入口。
- 既有停止、撤权、删除、未知调用结算和历史可读性保持成立。新增版本和迁移幂等，可分批执行、检查并回退入口。

### 13.3 模块边界

新增股友名册负责身份和版本；现有连接模块负责凭据与可用性；现有 Council / research-runtime 负责执行；团队层负责岗位、版本、持续约定和委托；资料/记忆模块负责来源与范围；paper-trading 负责策略与账本；telemetry 只采集和投影事实。

不通过新名册重新实现模型调用、工具执行或模拟交易。迁移不得将记忆权限、账户控制或密钥混入前端个人卡片配置。

## 14. 功能更新路线与阶段验收

这是跨模块的总体设计，每个阶段独立形成实现规格与任务。完整默认主线在 P2 交付后验收；P0/P1 的中间交付不得宣传为已完成自动团队。

| 阶段 | 交付内容 | 依赖与验收出口 |
|---|---|---|
| P0 独立股友基础 | 档案/版本、执行适配边界、记忆范围、岗位引用、运行身份及兼容迁移 | 同一人跨研究/团队可识别；同源模型不去重；撤权、版本固定与旧记录成立 |
| P1 新手主线 | 导入向导、一次 AI 设置、模板和描述式创建、进度恢复 | 复用 P0；不展开高级项也能导入并准备可用股友；幂等创建、失败恢复成立 |
| P2 自动团队 | 已有股友组队、持仓快照、持续约定、周期委托、自动决定/应用、暂停恢复 | 复用有限委托与模拟执行；一个完整周期可追溯，重复调度不重复成交，跨周期额度不能绕过 |
| P3 日常研究与复盘 | 单聊/多人显式选人、有限收束、股友/团队/版本分析 | 使用 P0/P2 关联；终态、用户停止、部分交付和未知观测正确展示 |
| P4 外部 A2A | 发现/鉴权/注册、协议适配、有限调用、状态/取消/产物与观测 | 基于真实支持的服务端联调；超时、未知结果、权限撤销和不支持能力均可处理 |
| 后续 RL 实验 | 可重置任务环境、数据集、基线、训练适配与候选版本验证 | 与本轮独立；有权重更新记录、独立测试和可复现结果后才能宣称 RL 改进 |

P0 就采集必要身份和轨迹引用，不能等 P3 才开始补关联。A2A 的接口在 P0 预留，P4 才对用户标记为可用。每阶段分别更新中英文文案、受影响架构图、使用说明和开发技能资料。

### 15.2 新手可用性验证

在具备测试所需输入和连接前置条件的环境中，招募至少五位首次使用者，不提供口头指导。目标至少四位完成导入、添加股友、创建并启动团队，并能正确解释：

1. 团队操作使用模拟资金与独立模拟账本。
2. 后续实盘变化不会自动同步到团队模拟盘。
3. AI 工作可能产生费用，在哪里查看与调整限制。
4. 如何暂停团队，以及暂停会影响什么。

记录每一步完成情况、求助、回退、错误理解和退出原因；未达标则修正流程。该目标尚未执行，不能以代码测试或页面截图代替通过证据。

### 15.3 核心契约验证

- 同一股友多团队记忆隔离；分享保留来源，撤权后禁止后续使用；个人私聊不隐式进入团队。
- 版本变更不改写历史和在途快照；撤销权限立即阻止迟到发布与应用。
- 周期租约、预算预留、重复确认、进程重启与未知远端任务均不造成重复研究派发或重复成交。
- 自动动作记录系统/agent 与运行约定；越界动作、资料失效和账户修订冲突不能通过最终校验。
- 模拟快照与后续实盘更新隔离；现金/行情未知不伪造为零；不同市场执行沿原规则检查。
- 主持人失败、部分股友失败、共享 CLI 忙、达到预算和用户停止均可结束或明确进入核对状态。
- 遥测未知值、父子成本去重、真实模型身份和完整性准确；不会因为看分析页而触发研究。
- A2A 使用真实支持的协议服务验收；只有 mock 或文档不算接入完成。

实现时使用虚构数据、隔离数据库和 fixture 助手验证；不得为测试触发个人付费研究或操作真实持仓。
