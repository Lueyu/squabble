# UI 细节整改与确定性验收

用户提供的 AUTO-UI SOP 用于本轮现有界面整改。保持当前产品结构、品牌色、字体、圆角、阴影、间距刻度及断点，只处理可复现的对齐、溢出、换行和点击区域问题。

## 方案与边界

采用现有 React/Vite 构建和仓库固定的 Playwright，通过仅监听回环地址的虚构 HTTP 夹具渲染实际客户端。夹具不连接个人数据库、不转发 API、不调用模型。固定场景矩阵包含常用路由、中英文、长文本、移动与桌面，以及股友编辑弹窗。

相比仅人工改 CSS，此方案保留 selector、rect、计算样式与前后截图；相比原样部署整套夜间自动修复，此方案先建立可验证的手动整改闭环。当前仓库没有签署过的 UI 基线，因此 before.json 只是本轮比较证据，不能冒充正式批准的 baseline.json。

探针与审美审查分工明确：探针测量页面横向溢出、显式声明的同行卡片操作区对齐、按钮换行和最小点击区域；Vercel web-design-guidelines 用于解释和复查，不参与修改阈值。内容性差异、刻意滚动的表格及未声明的组件对齐不泛化为自动缺陷。

## 文件隔离

- 扫描工具：scripts/ui-probe/ 与 .ui/，独立任务维护。
- 股友卡片：client/src/features/agent-roster/，独立任务维护。
- 共享弹窗与实际扫描命中的其他布局：主任务按证据逐项处理。
- 文档、npm 命令和最终验收：主任务串行整合。

不修改金融、研究、策略、权限或持久化契约；不新增自动夜班、付费视觉服务、部署或自动批准基线。后续若引入正式基线，由人审核截图与矩阵后单独批准。

## 验收

相同矩阵、相同 token 指纹与完整场景覆盖下进行 before/after 比较。缺页、脚本错误、矩阵变化、token 变化、新增 P0/P1 或总债务不下降均不能放行。每条产品修复必须对应实测证据，并查看其前后截图。

运行工具合成测试、相关现有客户端测试、lint、Web 构建及 context 检查。记录未覆盖的路由、状态和视觉判断；不把 DOM 断言等同于完整可访问性认证或人类审美批准。
