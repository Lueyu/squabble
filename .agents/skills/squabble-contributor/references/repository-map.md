# Repository map

Browser source collection lives in `server/modules/data-library/browser/` (runtime,
rendered content and authenticated public-address egress), `data-browser.service.ts`
(encrypted owner/source connections) and the existing `data-library.service.ts`
(durable jobs/versions). Migration51 adds mode/session/lease and version provenance.

connection controls are in `features/data-library/BrowserConnectionPanel.tsx` and
`CaptureModeFields.tsx`; user/runtime limits are in `docs/browser-source-collection.md`.

## Infrastructure and data ownership

- API tool runtime: `server/modules/council/council-tool-runtime.service.ts` binds original member/turn evidence and source authority to `research-runtime/`. `research-core/model-step.service.ts` and `ai-sdk-model.adapter.ts` perform one paid generation with SDK retries/execution/approval disabled. Journal/dispatch/invocations retain encrypted receipts, exact identities and unknown reservations. `research-runtime/drivers/` contains the controlled wrapper and actual read-only Deep Agents alternate; one loop owns execution at a time.
- Outbound capabilities: `server/modules/tool-connections/` owns owner-approved versioned MCP/provider catalogs and credentials; `tool-actions/` owns editable previews and dispatch-time confirmation. `/settings/tools` is composed from `client/src/features/tool-connections/`; `/settings/mcp` remains inbound scoped integration. No general HTTP tool proxy or owner-provided stdio command exists. See `docs/agent-tooling.md`.
- Complete datasets and private artifacts: `data-library/data-dataset.service.ts`, `research-artifacts/`, `research-compute/`, schemas `agent-tooling`, `research-artifacts`, `tool-actions`, `tool-connections`, `research-compute`, `deep-agent-driver` and migrations53–58. `data-library/documents/` owns local Docling/MinerU adapters and `document-jobs.service.ts` owns durable parse receipt/recovery. `data-library/providers/` adds AKTools/Tushare. `workers/documents/` pins optional side services; `workers/analytics/` is the separately licensed fixed-template Python worker. Real service quality acceptance is distinct from offline fixtures.

- V4 navigation: `client/src/features/navigation/` owns the eight roots, safe return destinations, history and content-scroll/hash restoration. `workspace-navigation.css` must keep the desktop top bar visible over old simple-experience styles. Interview flow controls portal into this fixed header; legacy direct links remain valid.
- Strategy interviews: `client/src/api/strategy-interviews.ts`, `features/strategy-interview/`, `server/modules/paper-trading/strategy-interview.controller.ts`, `strategy-interview.service.ts`, `strategy-interview.rules.ts`, `shared/strategy-interview.interface.ts`, migration `46_strategy_interviews.sql`. Saved review restoration is a GET, never a new preview POST.
- Companion display: `features/companions/` composes shared `components/AnimalAvatar.tsx`. Migration `47_portfolio_companions.sql` stores explicit identity/revision; policy and funds do not change when identity changes. Four starting origins are in the simulation seed JSON, not a new trading mode.
- Daily/visible memory: `server/modules/experience/daily-workspace.service.ts` reads saved facts in a read-only transaction; `research-memory.service.ts::inventory` exposes owner-only source pagination. A selected memory detail uses its exact ID, not only a symbol list capped at 100 records. See `docs/v4-daily-and-memory-workspace.md`.

- Shared research infrastructure: `server/modules/research-core/research-core.module.ts` owns LLM calls, evidence/source adapters and portfolio context. Both current research and retained analysis consume it; it does not import their orchestration. `research-errors.ts` owns shared sanitized failure codes. The legacy rating-to-holdings command remains in `multi-agent.service.ts`.
- Executor selection: `server/modules/research-routing/research-routing.module.ts` exports `PortfolioResearchRouteService` to Experience and PaperTrading. Routing selects existing configured executors; it does not stage research. Settings retains its pre-existing local LLM provider to avoid changing global initialization in this refactor.
- Strategy UI: `client/src/features/investment-strategies/` owns the editor, source dialog and list. Start with `InvestmentStrategyEditor.tsx`, then `use-investment-strategy-editor.ts` for saved state, receipts and explicit application, `StrategyEditorForm.tsx` for edits, and `StrategyExecutionReview.tsx` for saved authority. Pages only compose the feature.

- Composition: `server/main.ts`, `server/app.module.ts`, `server/modules/view/view.controller.ts`. `ViewModule` stays last for the SPA fallback. Development runs Vite/Nest separately; the web production build serves the client through Nest.
- Auth: `server/modules/auth/` and `server/common/platform/`. Protected controllers obtain owner from `req.userContext.userId`. Local mode selects a workspace identity; account mode uses sessions. Services and joins enforce owner scope; do not claim universal PostgreSQL RLS. See `docs/development.md` for identity selection and local-mode binding.
- Database startup: `server/common/platform/database.provider.ts`; base definitions/exports: `server/database/schema.ts`, with domain `*.schema.ts` siblings. Fresh SQL: `scripts/db/01_schema.sql`. The provider's registered migration list is authoritative; numbering is not contiguous (no registered `38` at this baseline).
- Research: `server/database/council.schema.ts`, `simple-council.schema.ts`, `research-documents.schema.ts`, `research-analysis-requests.schema.ts`, `research-memory.schema.ts`, `simple-experience.schema.ts`. Sessions/checkpoints, immutable versions, mutable current projections and durable receipts have different lifecycles.
- Strategy/simulation: `server/database/portfolio-workspace.schema.ts` owns account assignments and saved combination drafts/previews/revisions; `server/database/user-investment-strategies.schema.ts`, `user-strategy-runtime.schema.ts`, `investment-policy.schema.ts`, `strategy-mandates.schema.ts`, `strategy.schema.ts`, plus paper tables in `schema.ts`. Confirmed strategy, installed combination/policy revision and simulated fill are separate records. Each account compiles one profile/mandate from enabled assignments. Migration 45 keeps historical index names account-scoped and migration 42 recognizes combination authority on repeated startup.
- Channel: `server/database/channel.schema.ts` owns reports, facts/cards, briefs, findings/seals, episodes, events, bubbles, outbox, preferences, memories and reflections. `server/modules/channel/channel-runtime.ts` reads authoritative strategy/simulation records; channel prose is not execution authority.
- Real ledger: holdings/transactions/closed/cash tables in `server/database/schema.ts`; `server/database/asset-ledger.schema.ts`, `transaction-imports.schema.ts`, `import-batches.schema.ts`. These do not share the paper account/position ledger.
- Data/providers: `server/modules/quote/`, `server/modules/fx/`, `server/modules/settings/model-connections.service.ts`, `server/modules/llm-budget/`. Encrypted credentials and native-task files are private runtime data, not fixtures.
- Optional paths: `server/modules/mcp/` exposes scoped agent sessions. `agent/` is a Python CLI scaffold, not the built-in orchestrator. `desktop/` retains Electron/database/companion code. `deploy/` contains earlier public-beta artifacts, not the current development entrypoint.
